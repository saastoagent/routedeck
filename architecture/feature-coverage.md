# RouteDeck Feature And Architecture Coverage

Last updated: 2026-07-22

This is the canonical capability coverage matrix. It answers five maintenance
questions for every supported feature: what RouteDeck guarantees, what the
consumer owns, where the implementation lives, which document defines it, and
which focused check protects it.

The matrix describes implemented behavior only. Future work is listed
separately and must not be inferred as available. The verified cross-owner
trace for the 2026-07-20 boundary remediation is
[`knowledgebase/runtime-boundary-implementation-coverage.md`](../knowledgebase/runtime-boundary-implementation-coverage.md).

## Explicitly Not Implemented

- RouteDeck does not compile or own a product LangGraph topology.
- RouteDeck does not own authentication, users, organizations, tenants, or
  authorization policy.
- RouteDeck provides the required `RouteDeckSessionSelector` seam but does not
  implement authentication, principal/session listing, or a product's
  principal-aware opaque multi-session adapter. The Medusa reference explicitly
  selects guest-cookie mode for its local HTTP demo.
- RouteDeck does not invoke Medusa or any product tool directly.
- No document in this matrix claims a current release or live E2E pass; only the
  output of the named command can make that claim.
